# Math Arcade v0.8.1 — Phase 2 implementation checkpoint (sound on student iPads)

**Status:** Implementation checkpoint. Not tested on an iPad, not merged, not deployed.
**Branch:** `implement/v0.8.0` (on top of Phase 1). Spec: [v0.8.0](../change-specs/v0.8.0.md) §4 (B1). Version 0.8.1 (U-01: page contents changed after the 0.8.0 checkpoint).

## Diagnosis (from source, 15 October 2026)

- Most games play sound through Web Audio. On iPadOS, Web Audio is muted by the side switch / silent mode unless the page asks for "playback" audio; nothing asked. Vault 7's music is an `<audio>` file, which is why it was the one game heard.
- Every host started audio only after a network request, never directly inside the student's tap.
- A "Sound off" tap was remembered on the iPad and silenced Coastal, Nightfall 1, False Haven and Blackout for every later student.
- Some Sound buttons could throw and stop updating (Coastal / Nightfall / False Haven).
- Journey's synth is very quiet (no master volume).

## Changes

- `public/audio-unlock.js` (loaded before the app): playback audio session (silent looping `<audio>` on iPads without it); every tap, click or key resumes any suspended game audio; a game's `resume()` never leaves it waiting; sound-off memory cleared on each page load so music starts by default.
- Sound buttons in False Haven, Blackline, Journey, Blackout, Kingsgate, Coastal, Nightfall 1 and Ironbreak recover instead of throwing.
- Journey (Arcade wrapper only): 3× gain through a limiter.
- Chrono, Olivia, Math Civ (`campaign-runtime.js`): playback audio session; taps resume audio and retry music that iOS refused.
- Canonical game code (vendored from MathQuest) is unchanged.
