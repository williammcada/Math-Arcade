## Design and retained behavior

Use Cloudflare Workers plus a separate SQLite-backed Durable Object, matching MathQuest's backend infrastructure family. Serve app and API on the same Worker origin with Static Assets; no cross-origin cookies, new relay credential protocol, or changes to MathQuest. This is not the identical school-network route. Keep QR links rooted at the actual app origin, HttpOnly/SameSite cookies, exact POST Origin checks, strong teacher-password hashing, token hashing and role isolation.

Retain seven games, all canonical source snapshots, 312 shared math skills, one start gate per action round, native Chrono/Olivia gates, gate-free Math Civ, touch/input recovery, teacher approval, class/individual assignments, pause/resume/end, authoritative rounds, campaign leases/revisions, export and scoped deletion. Journey remains excluded. No retiming or source game edits.

## Implementation

- Extract storage-independent model; retain Node SQLite adapter as reference/local compatibility host.
- One Durable Object owns the teacher workspace. Synchronous SQLite transactions wrap each model operation. Large JSON state spans bounded rows, with only changed chunks written; preserve Unicode boundaries. Throwing operations roll back. Restart pauses existing rounds without resetting life/time budgets.
- Shared API command dispatch. Worker-first asset routing authorizes every adventure path before static delivery, including encoded aliases; protected assets are private/no-store. No state/test fixtures are published as assets.
- Wrangler configuration declares a new `math-arcade` Worker, `ARCADE` binding, SQLite migration and explicit same-origin asset behavior. Teacher password is a secret; never commit or log it.
- v0.3.0-rc.1 in package, health, main page and generated campaign page titles/visible credits. Vendor HTML remains byte-for-byte pinned.
- Add real workerd regression tests and gate both verification and canonical-source promotion on them. Production deployment is separate from source synchronization.

## Operation and limits

This retains the existing single-workspace state layout and is a classroom pilot, not a multi-school service. JSON parsing/serialization costs scale with retained work; 50 classes/100 students per class are input caps, not a verified concurrency promise. Cloudflare usage quotas/costs depend on the existing account; no paid upgrade is assumed. No production Node data exists in the recorded deployment history; no destructive migration or data reset is authorized. If an unrecorded deployment exists, export/preserve it before any import procedure is designed.

New Worker deployment requires Cloudflare authentication and ARCADE_TEACHER_PASSWORD. Match source SHA in `/health`, preserve build hashes and use the verified artifact. Keep source synchronization active, but do not silently deploy unverified upstream snapshots.
