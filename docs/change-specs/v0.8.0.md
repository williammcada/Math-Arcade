## 2. What the code does today (baseline facts)

- **QR:** drawn at a fixed 112 × 112 px (`public/base.css`), no enlarge control.
- **Class code:** the QR link pre-fills `?code=`, but the field stays editable; students could delete it.
- **Password:** one 4-letter password for the whole class, **single-use, 45 seconds** (`server/join-password.mjs`). After one student uses it, everyone waits until it expires.
- **Admission:** each student is admitted one at a time; no "Admit all".
- **Removing students:** only permanent deletion of a student's record; no way to sign out everyone while keeping the class's math.
- **Math settings:** stored per class (`c.config`); no saved sets and no copying to another class. Roster can only be added to.
- **Sound:** every host starts audio only *after* a network request, never directly inside the student's tap; no code sets the iPad audio session, so the side switch / silent mode mutes most games. Vault 7 is audible because its music is an `<audio>` file, which iPads don't mute the same way. Several "Sound on" buttons start in the wrong state, so a student's first tap turns sound **off**. Journey's music is also very quiet.
- **D-pads:** Nightfall 1, False Haven, Journey and Ironbreak use a 4-button inverted-T; Coastal uses a 3 × 3 slide pad; Vault 7 and Blackline have left/right only; Chrono and Olivia have their own pads. None match Mega Man Math.
- **Answers:** each part of the Engine treats equivalent forms differently (e.g. some fraction items reject 1.75 for 7/4; some reject 1 3/4). Every gate shows the same generic "Not quite." The Arcade calls the Engine's plain correct/incorrect check, not the version that explains *why* (e.g. "write it in simplest form").

## 3. Phase 1 — Teacher desk and joining

### A1. Enlargeable QR code
- Tapping the QR (or an **Enlarge** button beside it) opens a large view: QR at **300%** (336 px) or as large as the screen allows, with the class code underneath in large type.
- Size control in the large view: 100% / 200% / 300% / **Fit screen**. The last choice is remembered on that teacher computer.
- Close with ✕, Esc, or a tap outside.
- The QR must stay sharp at every size (re-drawn at the new size, not stretched).

### A2. Class code locked after a QR scan
- When a student arrives through the QR link, the class code shows as a fixed label (e.g. "Class: 7B — code A1B2C3D4"), not an editable field.
- A student who typed the address without the QR still gets a normal code field.
- Small "Wrong class? Scan the QR again" note instead of an edit control.

### A3. Universal class password
- **One password for the whole class**, shown large on the teacher desk.
- **Reusable:** any number of students can use the current password. Using it never "spends" it.
- **Refreshes every 30 seconds**, so a photo of the board goes stale. A countdown shows on the desk.
- **Grace period:** the previous password is still accepted for **10 seconds** after it changes, so a student who is mid-typing is not rejected. (Approved.)
- Teacher keeps a **New password now** button.
- Teacher admission still applies (A4), so the password alone never admits a device.
- The one-device-per-student rule stays: admitting a student's new device signs out their old one.
- Rate limit on join attempts stays.
- U-02 help `?` beside the password explaining the above.

### A4. Admit all
- **Admit all (N)** button at the top of "Students waiting to join". Admits every waiting student in one tap.
- One tap, no dialog. A student waiting on **two** devices is not admitted by Admit all: the desk names them and the teacher picks the right device with the individual buttons.
- Individual **Admit / Decline** buttons stay.

### A5. Change classes without re-choosing math

Owner's routine: class of 23 finishes → remove everyone → bring in the next class's roster → same math for the rest of the day.

**Approved design (both routes provided):**

- **Saved math sets.** "Save this math as…" stores the current skill selection, question count and settings under a name ("Thursday fractions"). "Use a saved math set" applies it to the class in one tap. Sets are teacher-wide, not per class.
- **Sign everyone out.** One button signs out every student device **without deleting** the students or their history, and **keeps the math**. The session and class code stay open, so the next group can join straight away (or the teacher can end the session as before).
- **Replace roster.** "Add students" gains **Replace all names** next to the existing add. Replacing permanently removes the old students' records, so it follows U-09: shows the count of students affected, offers export first, needs confirmation, has Cancel. The class's math is kept.

Using these, the owner can either (a) keep one "period" class and replace its roster each period, exactly as described, or (b) keep each class as its own class and apply the saved math set to it.

## 4. Phase 2 — Sound on student iPads (B1)

- **One Arcade-level sound unlock** that runs **immediately inside the student's tap** on Start/Resume (and on any Sound button), before any network request:
  - set the iPad audio session to playback (`navigator.audioSession.type = 'playback'` where supported) so the silent switch does not mute game sound;
  - start a tiny silent looping `<audio>` element (older iPads);
  - create/resume each game's own audio in that same tap.
- **Fix Sound buttons** in every game: label shows the real state; if sound isn't running, a tap turns it **on** (never off first); fix the Coastal / Nightfall / False Haven toggle error.
- **Journey:** raise music/effects volume to match the other games (add a master volume).
- **Math Civ and Chrono:** start sound on a real tap (`click`/`touchend`), and retry until it works.
- **Shared mute memory:** a "Sound off" choice made by one student no longer silences four games for every later user of that iPad; it lasts for that student's session only.
- **Music starts by default in every game.** No game opens silent; a student can still turn sound off for their own session.
- Teacher-desk note: sound plays on the student iPad; headphones recommended.

## 5. Phase 3 — One D-pad (C1)

**Reference:** Mega Man Math (`private-shell.template.html` line 39 and styles):
- Cross-shaped pad, **bottom-left, overlaid on the game**, 144 × 144: Up and Down 48 × 48; Left and Right widened to 72 px and meeting in the middle (no dead centre cell).
- Square corners; dark translucent buttons; pressed highlight.
- Action buttons **bottom-right**: two large round buttons (B, A) in red, smaller rectangular buttons below where a game needs more.
- Slide a finger from one arrow to another and the direction follows.
- Hidden while a math gate is open. Slightly smaller on short screens.

**8-direction version (owner, 2026-10-15):** the same Mega Man cross, but the four corner cells also hold arrow buttons (↖ ↗ ↙ ↘), so the pad is a full 3 × 3 of directions around the centre with **no empty space**: wherever the thumb lands it is on or next to a direction. Slide between cells to change direction. Used where a game needs diagonals.

**Implementation approach (U-10):** build both layouts **once** in the shared held-input mechanism the Arcade already uses (`/coastal/engine/`), keep U-10's release/interruption handling, and switch each listed game to it. No game gets its own copy.

## 6. Phase 4 — Math answers (Math Engine first)

Under U-14, these are Engine changes recorded in a separate Engine change spec (target Engine 0.35.0), then pulled into the Arcade deliberately.

### D1. Equivalent answers
**Proposed rule:** if the student's answer has the **same value**, it is correct — improper fraction, mixed number or decimal (7/4, 1 3/4, 1.75) — **unless the question explicitly asks for a form** ("as a mixed number", "in simplest form", "as a decimal").
- When a form is required and the student gives the right value in another form, the gate says so: "Right value — write it as a mixed number." (not "Not quite").
- Same tolerance for harmless typing differences everywhere: spaces around `/`, leading `.5`, trailing zeros `0.50`, `+` sign, `- 3/4`.
- Every skill gets a written answer type the Arcade can show as a short hint ("Fraction or mixed number", "Decimal to the nearest hundredth").
- Arcade switches to the Engine check that returns the reason, so students see specific feedback.

### D2. Repeating decimals audit
- 54 game questions today say "fraction, mixed number, **or terminating decimal**" but have answers that never terminate (e.g. 28/15, 7/3). Fix the wording ("exact fraction or mixed number") so no student tries a decimal that can't be exact.
- Repeating-decimal questions accept the standard written forms: 0.(3) **and** 0.3 with a bar, plus the equivalent fraction unless the question asks for decimal form.
- Rounding is accepted only when the question states the place value and rounding rule (U-04).

### D3. Answer pad
- Replace the flat text line with an answer pad that has:
  - a **fraction button** that opens stacked boxes (whole number | numerator / denominator) for mixed numbers and fractions;
  - a **repeat bar** key that draws a bar over selected decimal digits;
  - only the keys the question needs (no stray `x + × ^` on a decimal question).
- The iPad keyboard no longer pops up for keypad questions.
- Same pad in Kingsgate's between-wave questions and the campaign games.
